# Decisions

One line each: decision — alternatives — why.

- Branch `recording-first` is cut from `main` (which equals `beat-first`) — continue on `beat-first` — the brief says to branch from `main`; both point at the same commit.
- Project file uses serde 1.0.229 + toml 1.1.8 (both released Jul/Oct 2026, heavily used) — hand-written TOML writer/parser — derive-based (de)serialisation is far less code and less error-prone.
- Internal sample rate is fixed at 48 kHz; every source is converted on load with a windowed-sinc resampler — render at each source's own rate — one rate makes clip maths sample-exact, and 48 kHz is what most current audio hardware runs at.
- Sources are mono (stereo files are downmixed) — keep stereo sources — the whole engine (pitch tracking, slicing, stretching) is mono; stereo comes from pan and stereo effects. Revisit if people import stereo loops.
- `hummr new NAME` creates `NAME/NAME.hummr` plus `NAME/sources/` — `NAME.hummr` in the current folder — a folder per song keeps sources from colliding and makes a project easy to move or zip.
- Imported WAVs are copied byte for byte into `sources/`; in-app recordings are written as 32-bit float WAV — always re-encode — byte copies guarantee "never edit originals".
- Timeline positions are in beats, source regions in seconds — everything in seconds — beats make tempo changes re-time sliced/notes clips for free.
- Undo/redo stores whole-song snapshots — diffs/commands — a Song holds no audio (sources are Arc buffers outside it), so a snapshot is a few KB and snapshots can't get out of sync.
- Clip "speed" means time-stretch that keeps pitch, "pitch" means pitch-shift that keeps length — tape-style varispeed — that's what non-musicians expect from two separate sliders.
- Effects on a clip/track are: a named preset with an amount macro, four friendly sliders (drive, filter, echo, reverb) and a list of raw effects — one flat list of effects — matches "presets first, sliders, raw parameters one level down".
- Track pan is a linear balance (centre = unity), clip pan is constant-power — constant-power everywhere — tracks are already stereo after effects; balance keeps the centre level unchanged.
- Splitting a repeated clip first unrolls it into one clip per repeat — refuse, or a partial-repeat model — simple, predictable and keeps the model small.
- Clip fades default to 0 so split-then-play is sample-exact; sliced clips use 5 ms complementary crossfades at the cuts — always declick clip edges — exact splits are an acceptance requirement.
- A project whose source file is missing still opens; that sound is silent and a warning says which — refuse to open — losing access to the whole song over one file is worse.
- MIDI drum parts go on channel 10 (`SongTrack::drums`) — keep drums on a melodic channel — General MIDI players expect drums there.
- Onsets: log-magnitude spectral flux (SuperFlux-style max filter, 2.7 ms hop) with peaks refined to the attack on a >500 Hz envelope — plain energy onsets — flux finds soft hits; the high-passed refinement keeps hats on top of a ringing kick accurate to <1 ms.
- Tempo: autocorrelation of a body-weighted flux curve × a log-normal prior at 115 BPM, refined by a comb fit and a least-squares line through on-beat hits, then a two-way octave check on a *power* flux curve (halve if alternate pulses are < 0.3 as loud, double if the half-speed grid misses hits and the doubled pulse is even) — prior alone — the prior alone got 160 BPM loops as 80 and 60 BPM loops as 120.
- Synthetic test loops are rock, syncopated-kick and four-on-the-floor patterns — also a half-time pattern with kicks on off-beats — that half-time pattern is genuinely ambiguous (a drummer could count it either way), so it can't fairly define "correct".
- Beat confidence = (hit strength on the 8th grid beyond chance) × (fraction of beats that have a hit) — grid alignment only — fitting a tempo to random hits made grid alignment alone look "sure" (0.54); coverage drops random hits to ≤ 0.34.
- Slices are cut 4 ms before each attack with 5 ms complementary crossfades; each slice stores its attack offset and its unsnapped position so the snap strength is re-computable — destructive snapping — the inspector's strength slider must be reversible.
- Snapping lines up a slice's *attack* (not its cut point) with the grid — snap cut points — the attack is what you hear as "on the beat".
- A sliced clip moves by under half a beat so its own beats sit on song beats — keep its start — otherwise a perfectly cut loop can still be off the song's grid.
- Attack refinement walks back from the peak until the envelope stays quiet for 1.5 ms — stop at the first quiet block — noisy snares dip inside the hit and were placed 13 ms late.
- The M3 test loops jitter per time slot (a kick and hat meant together move together); the M2 tempo test keeps per-drum jitter — per-drum jitter everywhere — independent jitter makes 30 ms flams that no slicer can treat as one hit, and a beatboxed sound covers both drums at once.
- "Match to song" defaults: rhythmic clips (≥ 2 hits/s and confidence ≥ 0.3) are cut and snapped to 1/8 at full strength; others keep their sound — always stretch — matches the brief, and cutting keeps drums crisp.
- `hummr snap` defaults to a 1/16 grid and strength 1 — 1/8 — beatbox hats are often 16ths; 1/8 would pull them onto the wrong line.
- Time-stretch is WSOLA with 42 ms Hann frames, 50% overlap and a ±12 ms coarse-to-fine similarity search — phase vocoder — WSOLA keeps a single voice clean with no phasiness and is simple to make exact-length; drums are handled by slicing instead.
- Pitch-shift = stretch by the pitch ratio, then windowed-sinc resample back — a separate pitch-shifting algorithm — reuses two tested pieces; formants move with pitch (documented in LIMITS.md).
- Effects are a per-clip/track/master `FxChain` of one preset + amount, four plain sliders (drive, reverb, echo, filter) and an optional raw effect list — a free-form plugin chain only — the inspector stays one screen of simple controls; raw effects keep the file format open for later.
- Every preset is a recipe interpolated by its amount (frequencies exponentially), so amount 0 is exactly the dry signal — fixed preset settings plus a wet/dry knob — wet/dry on distortion/bitcrush mixes two loudly different signals and sounds like two layers.
- Reverb is Freeverb (8 combs + 4 allpasses, right channel spread by 23 samples) — convolution with a generated impulse — no impulse files, cheap, deterministic, well known.
- Echo time is in beats (default 3/4) so it follows the song tempo — milliseconds — echoes on the beat are what people want by default.
- Effect tails are rendered past the clip end and trimmed once below −90 dB — cut at the clip end — reverb/echo tails cut off audibly.
- Master bus ends in a 5 ms look-ahead limiter at −1 dBFS, transparent below the ceiling — a clipper — no added distortion on loud mixes; exported files never clip.
- Noise cleanup is power spectral subtraction (43 ms Hann frames, 75% overlap) with over-subtraction 1+3·strength, a gain floor of −40·strength dB, and gains smoothed over 3 bands and ~2 frames — Wiener filter / RNNoise-style model — no model files, deterministic, and enough for steady hiss and hum, which is what the brief asks for.
- The noise is learned from a user-marked region, or else the clip's first 300 ms (as the brief specifies) — quietest half second / per-band minimum statistics — the brief asks for a manual tool with that default; minimum statistics treat a steady sung note as noise.
- Cleanup is a clip setting (`clean`, `noise_region`) applied at render time to a copy of the source — rewrite the source file — keeps editing non-destructive and the strength adjustable.
- Added `hummr clean in.wav [--strength] [--noise START:LEN]` — TUI only — gives a scriptable, testable way to use cleanup before the timeline exists.
- Voices sit behind an `InstrumentVoice` trait (preview synth, sampler, drum kit; SoundFont in M8) — an enum match in the renderer — the brief asks for it and it lets the SoundFont voice drop in without touching the renderer.
- "Turn into" keeps the source region on the clip and only swaps `kind`, so "none" goes back to the recording — copy the notes into a new clip — conversions stay reversible and linked to the take.
- To notes: the existing transcriber runs on the (cleaned) region with the tempo fixed to the clip's own beats-per-second and the grid anchored at the clip start — detect tempo again — the clip already sits on the song's grid, so notes land where the sound was.
- Own sound: root = median YIN over the loud frames; notes play the trimmed sound pitch-shifted (WSOLA + resample), stretched up to 4× for longer notes and cut with a 10 ms fade for shorter ones; shifts fold by octaves past ±12.5 semitones — a fixed-length one-shot — sung "ooh" samples need to hold for long notes.
- Drum classification is three rules on the first 60 ms: kick if > 40% of energy is below 250 Hz and the centroid is under 800 Hz, hat if > 50% is above 5 kHz (or centroid > 6 kHz), otherwise snare — a trained classifier — no model files, explainable, and 100% on 300 seeded beatbox-style hits and 100 kit hits.
- Drum hits from a cut-and-snapped clip use the snapped slice positions — re-detect onsets — keeps the tightened timing.
- Beatbox test hits come from a separate synthetic generator (lip thump, band-passed "pf", high-passed "ts", random pitch/brightness/length) — reuse the kit drums — testing the classifier only on the sounds it replaces with would prove little.
- SoundFont playback uses rustysynth 1.3.7 (MIT, pure Rust, released 2026-10-01, actively maintained) — fluidlite/FluidSynth bindings — no C toolchain or system library needed, and it reads standard .sf2 files.
- No SoundFont is bundled — bundling a small GM font — the freely licensed GM fonts are tens of megabytes (FluidR3 ~140 MB) and the small ones (TimGM6mb) are GPL, which doesn't fit an MIT repo; the built-in synth is the fallback and the message says how to set one up.
- SoundFont path comes from `HUMMR_SOUNDFONT`, else `soundfont = "…"` in `$XDG_CONFIG_HOME/hummr/config.toml` (or `~/.config/hummr/config.toml`) — a CLI flag on every command — set once, works for edit and export alike.
- The SoundFont synth runs with its own reverb/chorus off — keep them on — Hummr's effects do reverb, and a dry synth is deterministic and testable.
- SoundFont tests build a tiny valid .sf2 (one looped sine) in code — check in a binary fixture — keeps the repo text-only and documents the file format.
- The timeline is a new `studio` module beside the old editor (which becomes the notes editor) — rewrite `App` into one screen — the old editor's 2,500 lines and tests keep working untouched, and the timeline starts from a clean model (the core `Song`).
- Waveform glyphs come from the source audio (audio clips map columns back to the source region, sliced clips to their slices, notes clips draw their notes) and switch to the rendered sound once the playback engine has it — always render first — boxes appear instantly and snapshot tests stay deterministic.
- Waveform height is a dB scale (−48 dB → ▁, 0 dB → █) — normalise each clip to its own peak — quiet takes should look quiet.
- Minimum terminal is 80×24 with a plain "terminal too small" message below that — the old editor's 64×18 — the brief's timeline needs 80 columns for a header column plus a useful number of beats.
